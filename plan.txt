# Project Goal

Build a lightweight, privacy-focused background location recording and reporting system for Android with a minimal UI.

The Android application operates primarily as a **background tracking service**. It requires a one-time login/registration and runs continuously in the background to capture and POST GPS telemetry to the Go API server. Map rendering, spatial visualizer, and UI-heavy map interactions are stripped from the mobile client to save bandwidth, battery, and development overhead.

Primary users:

* Couples
* Family members
* Close friends

The backend manages all location records, access permissions, and WebSocket distribution for external clients or dashboards.

# Key Architectural Changes

1. **One-Time Auth & Perpetual Login:** The Android app receives a long-lived JWT and Refresh Token stored securely in Encrypted DataStore. Auto-re-authenticates silently on boot.
2. **Headless Telemetry:** Mobile records GPS coordinates, activity, and device state, then issues background `POST` requests without rendering any geographical assets.
3. **Low Resource Footprint:** Eliminating map tile fetching and canvas rendering drops client CPU, RAM, and battery usage drastically.

# Core Features

## 1. Authentication (One-Time Setup)

* Register
* Login (Persisted indefinitely via refresh token flow)
* Auto-start service on boot (`RECEIVE_BOOT_COMPLETED`)
* Logout & Session Revocation

## 2. Background Location Service

* Persistent Foreground Service with low-priority notification bar.
* Smart interval polling based on activity & motion:
* Moving (> 15 km/h): Every 10 seconds
* Walking: Every 20 seconds
* Still: Every 5 minutes
* Battery < 20%: Every 10 minutes


* Offline queuing: Stores unsent coordinates locally and flushes to API when internet restores.

## 3. Friend & Sharing System (Minimal Text UI)

* Send / Accept / Reject Friend Request
* Request / Grant / Revoke Location Sharing Permission
* Simple textual list displaying friends' last seen time and battery status (No map).

# Database Tables

* `users`: Basic accounts and password hashes.
* `refresh_tokens`: Long-lived device tokens for persistent mobile logins.
* `friendships`: Bidirectional user relationships.
* `location_permissions`: Explicit sharing consent records.
* `locations`: Historical spatial data point logs.
* `devices`: Device-specific metadata and tracking configurations.
